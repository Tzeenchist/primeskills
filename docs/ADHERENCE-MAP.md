# Что вообще поддаётся замеру

В двадцати пяти скиллах 89 инвариантов. Проверить из транскрипта можно не те,
которые важнее, а те, которые **ограничивают наличие, отсутствие или порядок
вызовов инструментов**. Это единственный признак, который работает; всё
остальное — суждение о тексте, а его агент и выдаёт.

## Что проверяется сейчас — десять

| проверка | скиллы | по чему видно |
|---|---|---|
| красная фаза | `build`, `cycle` | правка тестового файла раньше исходника |
| прогон состоялся (G4) | `verify` | команда прогона в пролёте |
| зелень не куплена правкой теста | `verify` | между двумя прогонами правились только тесты |
| воспроизведение до правки (P3) | `debug` | прогон раньше первого `Edit` |
| не пишет (G16) | двенадцать `read-only` | `Edit`/`Write` или мутирующий шелл в пролёте |
| дифф до коммита (G17) | `land` | `git diff` раньше `git commit` |
| гигиена git (G14) | `land`, `merge`, `revise`, `build` | `git add -A`, `--force`, `rebase`, `--amend`, `reset --hard` |
| чекпоинт в репозитории | `handoff` | путь записи внутри `$HOME` вместо `.primeskills/handoff/` |
| порядок цепочки | пять потоков | порядок вызовов против объявленного `calls:` |
| цель разрешена до разрушения (G8) | вся сессия | печать цели внутри разрушительной команды |

Четыре из них — `гигиена git`, `чекпоинт в репозитории`, `порядок цепочки`,
`зелень правкой теста` — добавлены 2026-08-17 при сплошном разборе всех 89.
Они были различимы с самого начала; первая редакция их просто не заметила.

## Что различимо, но не проверяется

- **Бюджет чтения (G3)** — число `Read` в пролёте считается легко, и с
  2026-08-19 есть порог (двадцать на задачу, PS-041 п.9). В `adherence`
  проверка пока не подключена.
- **Счётчик попыток (G12)** — вызовы `primeskills-run fail` видны, но отличить
  «не вызвал» от «нечего было считать» из транскрипта нельзя.
- **Откат до выкатки** — `deploy` требует назвать откат прежде, чем начать.
  Различимо только по тексту ответа, а не по вызовам.

## Что не различимо в принципе

Больше половины инвариантов — суждения о содержании: «упрощай язык, а не
утверждение» (`baby`), «находка называет файл и строку» (`vet`), «пиши для
исполнителя без контекста» (`plan`), «аналогия обязана нести предсказательный
вес». Проверить их может только читатель.

Это не изъян набора и не изъян инструмента. Это граница метода: **соблюдение
измеряется там, где правило говорит о действиях.** Правило о качестве текста
измеряется чтением текста, и притворяться, что регулярное выражение на это
способно, было бы хуже, чем честно не проверять.

## Следствие для сокращения

Из десяти проверок восемь относятся к семи скиллам: `build`, `cycle`, `verify`,
`debug`, `land`, `merge`, `handoff`. Остальные восемнадцать проверяются только
запретом на запись — то есть про них статистика скажет лишь, вызывались ли они
вообще. Для PS-009 это значит: решение о сокращении по данным будет надёжным
для семи скиллов и слабым для остальных.
