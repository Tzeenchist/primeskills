# Правило → проверка

Каждое правило `core/` либо имеет механическую проверку (линтер, тест,
программа), либо честно помечено непроверяемым — со страховкой, которая его
держит. Непроверяемое без помечки — кандидат на удаление: оно занимает
контекст и создаёт видимость контроля.

Тест `tests/test_rule_coverage.py` требует, чтобы каждое правило из
`PRINCIPLES.md` и `GUARDRAILS.md` стояло в этой таблице. Новое правило без
строки здесь роняет гейт.

## Что сюда добавлять

Новое правило ядра получает строку здесь тем же коммитом. «Механика» называет
файл: линт-правило (F…/C…), тест (`tests/…`) или программу (`bin/…`).
«Страховка» называет, кто держит правило вместо машины — обычно конкретный шаг
конкретного скилла.
