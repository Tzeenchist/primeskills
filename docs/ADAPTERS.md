# Установка и ролевая изоляция

## Один источник правды

`bin/primeskills-install` связывает каталог `skills/` с каждым агентом. Ничего
не копируется — правка `SKILL.md` в репозитории действует во всех агентах сразу.

```
python3 bin/primeskills-install            # печатает план, ничего не меняет
python3 bin/primeskills-install --apply     # связывает
python3 bin/primeskills-install --uninstall --apply
python3 bin/primeskills-install claude --apply   # только один агент
```

| агент | куда | как |
|---|---|---|
| Claude Code | `~/.claude/skills/<имя>/` | настоящий каталог, файлы внутри — симлинки (так же ставится gstack; иначе `ref/` не виден) |
| Codex | `~/.codex/skills/<имя>` | симлинк на каталог |
| OpenCode | `~/.config/opencode/skills/<имя>` | симлинк на каталог |
| Kimi | `extra_skill_dirs` в `~/.kimi-code/config.toml` | симлинки не нужны, достаточно пути |

**Коллизии.** Установщик проверяет, занято ли имя чужим скиллом, и только тогда
добавляет префикс `prime-`. Сейчас коллизия ровно одна: `autoplan` у gstack в
`~/.claude/skills`, поэтому наш встал как `prime-autoplan`. Удаление снимает
только те записи, что ведут в этот репозиторий, — чужое не трогается.

## Ролевая изоляция: что проверено, а что нет

Десять аналитических скиллов (`brief`, `plan`, `ceo`, `eng`, `beauty`, `teams`,
`autoplan`, `vet`, `probe`, `baby`) не должны иметь возможности писать.

| агент | механизм | статус |
|---|---|---|
| **Claude Code** | `allowed-tools` во frontmatter | **работает.** Поле стоит в самих скиллах, поэтому переживает симлинк и не требует генерации. Линтер сверяет его с `role` (правило F10) |
| **Codex** | профиль `[profiles.prime-analyst]` с `sandbox_mode = "read-only"`, вызов `codex -p prime-analyst` | **проверено частично:** `codex doctor` разбирает конфиг без ошибок, флаг `-p prime-analyst` принимается. Что песочница действительно режет запись, живьём не проверялось |
| **Kimi** | `kimi --agent-file <путь>` | **не проверено.** Флаг существует по `--help`, формат файла не подтверждён. Профиль не создавался, чтобы не оставлять в конфиге то, что может не работать |
| **OpenCode** | профиль агента | **не решено.** Пробовал `~/.config/opencode/agent/prime-analyst.md` и ключ `agent` в `opencode.json` — `opencode agent list` не показал ни того, ни другого. Обе попытки откачены, конфиг чист. Бинарник скомпилирован, формат из него не вычитать |

Там, где механизма нет, остаётся текстовый запрет: у каждого read-only скилла
в инвариантах написано, что он читает и докладывает. Это слабее, и делать вид,
что это то же самое, не нужно.

## Mem0 — по флагу

Выключено по умолчанию. Включается `PRIMESKILLS_MEM0=1`.

Точек ровно две:

- **Чтение** — `plan` и `brief` могут поднять прошлые решения по проекту.
- **Запись** — шаг 7 в `land`: решение и его причина, редкий баг с корнем,
  отвергнутый вариант с обоснованием.

**Фильтр обязателен:** не писать то, что выводится из кода, `git log` или
`PLAN.md`. Без него память заполняется пересказом диффов и перестаёт работать.

Отсутствие mem0 никогда не ломает скилл: деградация тихая.
