# Установка и ролевая изоляция

## Один источник правды

`bin/primeskills-install` связывает каталог `skills/` с каждым агентом. Ничего
не копируется — правка `SKILL.md` в репозитории действует во всех агентах сразу.

```
python3 bin/primeskills-install            # печатает план, ничего не меняет
python3 bin/primeskills-install --apply     # связывает
python3 bin/primeskills-install --uninstall --apply
python3 bin/primeskills-install claude --apply   # только один агент
```

| агент | куда | как |
|---|---|---|
| Claude Code | `~/.claude/skills/<имя>/` | настоящий каталог, файлы внутри — симлинки (так же ставится gstack; иначе `ref/` не виден) |
| Codex | `~/.codex/skills/<имя>` | симлинк на каталог |
| OpenCode | `~/.config/opencode/skills/<имя>` | симлинк на каталог |
| Kimi | `extra_skill_dirs` в `~/.kimi-code/config.toml` | симлинки не нужны, достаточно пути |

**Коллизии.** Установщик проверяет, занято ли имя чужим скиллом, и только тогда
добавляет префикс `prime-`. Сейчас коллизия ровно одна: `autoplan` у gstack в
`~/.claude/skills`, поэтому наш встал как `prime-autoplan`. Удаление снимает
только те записи, что ведут в этот репозиторий, — чужое не трогается.

## Ролевая изоляция: что проверено, а что нет

Двенадцать аналитических скиллов (`brief`, `plan`, `ceo`, `eng`, `beauty`,
`teams`, `autoplan`, `vet`, `probe`, `baby`, `measure`, `study`) не должны
иметь возможности писать.

### Что из этого — гарантия, а что пожелание

Ни одна строка ниже не проверена состязательным тестом, поэтому «enforced»
означает «хост объявляет, что запрещает», а не «мы доказали, что обойти нельзя».

| гарантия | Claude Code | Codex | OpenCode | Kimi |
|---|---|---|---|---|
| `Edit`/`Write` запрещены у read-only | объявлено | объявлено, песочница здесь не работает | объявлено | объявлено |
| запись через шелл запрещена | **нет** | нет | **нет** | нет |
| выход за границу каталога запрещён | **нет**: хук видит только `Edit`/`Write`/`NotebookEdit` | нет | нет | нет |
| сетевой доступ ограничен | нет | нет | нет | нет |

Итог одной строкой: **ролевая изоляция у нас — намерение, а не граница
безопасности.** Единственный канал, который действительно перехватывается, —
редакторские инструменты у Claude Code. Всё остальное держится на том, что
модель читает инструкцию и следует ей.

`fence` — предупреждающий слой, а не ограждение: список опасных команд это
список, и шелл денилистом не закрывается. Настоящая граница требует песочницы,
разрешённого рабочего каталога и allowlist инструментов — этого у нас нет.

### Потолок принуждения

Записано 2026-08-18, после того как три внешних разбора сошлись независимо:
сильные принципы, слабое принуждение. OpenCode — «дефицитный ресурс не
контекст, а послушание»; Kimi — дельта над базовой моделью мала; Codex —
8/10 как набор привычек, 4/10 как слой безопасности. Прогон 6 показал это
фактом: `build` был вызван, его красная фаза проигнорирована.

Инструментов принуждения у нас ровно два, и оба дырявые по устройству:

- **хуки** — сильные, но односредовые (только Claude Code) и видят только
  `Edit`/`Write`/`NotebookEdit`; `sed -i` из `Bash` проходит мимо;
- **запись прогона** (`primeskills-run`) — работает у всех агентов, потому что
  это не перехват, а условие плюс проверяемое состояние; обходится тем, что
  агент просто не вызовет `run`.

Отсюда вывод, который стоит держать перед глазами, прежде чем строить третий:
**полного принуждения из этой позиции не построить.** Мы не владеем циклом
исполнения — только текстом и вспомогательными программами. Достижимый
максимум: сделать нарушение **видимым постфактум** (`primeskills-adherence`) и
**дорогим** (шаг не засчитывается без записи). Всё, что обещает больше, обещает
чужую власть.

Практическое следствие: машина состояний из разбора Codex и состязательные
тесты изоляции отложены не из лени. Строить принуждение поверх набора, про
который ещё неизвестно, вызывается ли он, — это повторить ошибку «добавить до
замера», на которой уже сгорели шесть стендовых плеч.

### Общее состояние на машину

`~/.primeskills/` — не «наш» каталог, а общий для всех четырёх агентов на этой
машине: `installed.json` пишет установщик, `lang` пишет `primeskills-help` из
любой сессии любого агента. Записанное там значение может появиться без ведома
того, кто сейчас работает.

Найдено на живом случае: `lang` со значением `ru` возникло 2026-08-17 в 15:21
и выглядело утечкой из тестов. Изоляция тестов оказалась ни при чём — это
сессия Codex, стартовавшая за шестнадцать секунд до того, выполнила шаг 3
скилла `primeskills`, ровно как там написано. Проверять надо было соседей, а не
тесты.

Состояние прогона (`.primeskills/run/`) устроено иначе — оно лежит в
репозитории, к которому относится, и общим не бывает.

| агент | механизм | статус |
|---|---|---|
| **Claude Code** | `allowed-tools` во frontmatter | **работает.** Поле стоит в самих скиллах, поэтому переживает симлинк и не требует генерации. Линтер сверяет его с `role` (правило F10) |
| **Codex** | профиль `[profiles.prime-analyst]`, вызов `codex -p prime-analyst` | **синтаксис верный, песочница в этой среде не работает** — см. ниже |
| **Kimi** | профиль `~/.kimi-code/agents/prime-analyst.md` | **работает.** Запуск с несуществующим профилем печатает список доступных, и `prime-analyst` в нём есть. `tools` разрешает Read/Grep/Glob, `disallowedTools` запрещает Edit/Write/NotebookEdit |
| **OpenCode** | профиль `~/.config/opencode/agents/prime-analyst.md` | **работает.** `opencode agent list` показывает `prime-analyst (primary)`. `permission: edit: deny, write: deny` |

### Codex: песочница здесь не работает вовсе

Синтаксис профиля подтверждён документацией и совпадает с тем, что у нас
записано: `[profiles.NAME]` с ключами `sandbox_mode`
(`read-only` / `workspace-write` / `danger-full-access`) и `approval_policy`
(`untrusted` / `on-request` / `never`).

Но проверка живьём дала другое. `codex sandbox` с записью файла:

| режим | результат |
|---|---|
| `read-only` | `bwrap: loopback: Failed RTM_NEWADDR: Operation not permitted`, файл не создан |
| `workspace-write` | **та же ошибка**, файл не создан |
| `danger-full-access` | отработало, файл создан |

То есть `bubblewrap` в этой среде сломан, и падают **оба** ограничивающих
режима, а не только read-only. Файл не появился не потому, что песочница
удержала запись, а потому, что команда вообще не запустилась.

Практический вывод: профиль `prime-analyst` с `sandbox_mode = "read-only"`
здесь «защищает» тем, что не даёт выполнить ничего, включая `git diff`, который
нужен `vet`. Это не изоляция, а неработоспособность. Там, где `bwrap` исправен,
профиль сработает как задумано; здесь для Codex остаётся `approval_policy`
и текстовый запрет.

Раньше в этой таблице стояло «проверено частично: конфиг разбирается, флаг
принимается». Разбор конфига и приём флага не говорят ничего о том, режет ли
песочница запись, — и это ровно та подмена, против которой написан G4.

### Как это нашлось

Четыре попытки угадать формат провалились: файл в `~/.config/opencode/agent/`
(единственное число), ключ `agent` в `opencode.json`, интерактивная
`opencode agent create`, проектный `.opencode/agent/`. Ответ был в
документации: каталог называется **`agents/`**, во множественном числе.
Одна буква.

Урок дороже самой правки: **прежде чем разбирать скомпилированный бинарник,
прочитать документацию.** Копание в `strings` не только не дало ответа, но и
стоило контекста — ровно то, против чего написан наш же G3.

Профили лежат в репозитории (`adapters/opencode/`, `adapters/kimi/`) и
связываются симлинками, как и скиллы: один источник правды.

Там, где механизма нет, остаётся текстовый запрет: у каждого read-only скилла
в инвариантах написано, что он читает и докладывает. Это слабее, и делать вид,
что это то же самое, не нужно.

**Второй источник, найденный не сразу.** После чистки `~/.codex/skills` Codex
по-прежнему показывал gstack: он читает ещё и `~/.agents/skills` — каталог по
межагентному соглашению `.agents`, на который не ссылается ни один конфиг. Там
лежала **отдельная полная установка gstack на 617 МБ** (не ссылки на копию для
Claude Code) и ни одного нашего навыка.

111 записей перенесены в `~/.agents/skills_archive`, остались только
`find-skills` и `modern-web-guidance` — они не из gstack. Перенос, а не
удаление: откат — `mv ~/.agents/skills_archive/* ~/.agents/skills/`.

Источник для Claude Code не тронут: `~/.claude/skills/gstack` на месте, 90
записей, набор продолжает работать. Список снятого с Codex —
`~/.mcp-disabled-backup-2026-08-17/codex-gstack-manifest.txt`.

**Открытым остаётся вопрос охвата:** `~/.agents/skills` — путь общий, и какие
ещё агенты его читают, конфигами не установить. У OpenCode свой каталог с
собственной копией gstack (35 записей), у Kimi в `extra_skill_dirs` только наш
путь. Если у кого-то gstack пропадёт — вернуть одной командой выше.

## Mem0 — по флагу

Выключено по умолчанию. Включается `PRIMESKILLS_MEM0=1`.

Точек ровно две:

- **Чтение** — `plan` и `brief` могут поднять прошлые решения по проекту.
- **Запись** — шаг 7 в `land`: решение и его причина, редкий баг с корнем,
  отвергнутый вариант с обоснованием.

**Фильтр обязателен:** не писать то, что выводится из кода, `git log` или
`PLAN.md`. Без него память заполняется пересказом диффов и перестаёт работать.

Отсутствие mem0 никогда не ломает скилл: деградация тихая.
