## 1. Ставка

**Факт:** замер честный — сравниваются реальные цепочки: `investigate` 8 222 слова против `debug` 432 после оплаченного `core` (bench/RESULT.md:11–15), и 92k — это проход из пяти скиллов с вложенными файлами (RESULT.md:25–27), не «все 55 сразу». Посылка для измеренного верна; про качество замер молчит — автор сам это признал (RESULT.md:69–74).

Где сжатие стоило настоящего:

- **Факт.** SKILL-SOURCES.md:190: gstack `browse` (7 578 слов) отброшен «целиком; используем playwright + chromium + `--no-sandbox`». Инструмента в наборе нет: probe/SKILL.md:2 обещает «click through a running app», в `allowed-tools` (строка 6) нет ничего браузерного. А процедура требует «each state was **produced**,» not imagined» (probe:37,41). У донора были слова плюс демон — здесь остались слова. Это и есть место, где выброшенное было нужно.
- **Вывод.** deploy: SKILL-SOURCES.md:239 отбросил `setup-deploy` (7 656) — «конфигурация окружения не наша забота». Тогда шаг 6 deploy/SKILL.md:36–38 («Release → verify: the process reports success») не имеет источника команды релиза ни в одном файле. Список Fly/Vercel автора не покрыл бы, но донорская идея — один раз записать процедуру релиза проекта — была нужна и выброшена.

## 2. Дыры в цикле

- **Сценарий:** PR открыт, через два дня ревьюер просит правки. Скилла «прочитать комментарии → принять/оспорить → доделать → запушить» нет (22 каталога в `skills/`). Фрагмент receiving-code-review вшит в vet как «право оспорить» (SKILL-SOURCES.md:170) — но vet работает до land; цикл после land владельца не имеет.
- **Сценарий:** verify зелёный, probe на веб-приложении — без инструмента (п. 1) агент либо выдумывает состояния, либо честно пишет NOT RUN; «ходить по приложению» набору нечем.
- **Сценарий:** «выкатывай» на Django-проекте автора на голом IP: deploy корректно разрешит цель (G17) и покажет откат — и остановится: процедуру релиза записывать негде.

## 3. Ограничители

**Вывод:** выживают G с наблюдаемым нарушением — G4, G6, G17 называют конкретный действие и вывод. Молча игнорируются:

- **G3** — бюджет чтения не измерим ничем; ни один инструмент в `bin/` не считает прочитанное.
- **G11** — «каждые 2–3 шага коммит» проигрывает пользовательскому «дальше»; наблюдателя частоты нет.
- **G9** — «One counter per problem, owned by whoever runs the loop» (GUARDRAILS.md): владелец умирает вместе с сессией. debug:52 учитывает попытки «here or in `build`» — внутри сессии. Через границу сессий счётчик обнуляется, если не сработал handoff.

Семнадцать правил при живых наблюдателях — около шести. Остальное деградирует до совета.

## 4. Композиции

**Факт:** release/SKILL.md — шесть шагов «Call X → verify → Ask». Порядок реален: 250 слов однозначны. Гейт — фикция: «Any stage stops: the flow stops there» (release:33) держится только текстом, а «Each stage reads the previous one's evidence» (release:18) — evidence живёт в разговоре, не в артефакте; новая сессия цепочку не восстановит. Нагруженное место, которое нельзя трогать при переделке: шаги 2 и 4 держат решения merge/deploy у пользователя — flow не может проехать их молча.

## 5. Кому, кроме автора

- **Факт** (status): изоляция ролей enforced у OpenCode/Kimi; у Claude Code «the shell is not covered (G7)»; у Codex «sandbox unusable». На двух из четырёх агентов G7 не работает — второй пользователь наследует это как свойство набора.
- `vendor/` в .gitignore (README.md:29) — проверка утверждений SKILL-SOURCES другим человеком требует переклонов.
- routing-тест лексический, тестовые запросы повторяют лексику descriptions (review:44) — чужие формулировки не покрыты.
- bench — одна задача, чистая функция на Python (RESULT.md:3); диалоговая половина не обкатана (README.md:49–51).

Нужно: второй проект, вторая машина, один живой `land→merge→deploy` на чужом репозитории.

## 6. Сильнейший довод против

Дефицитный ресурс — не контекст, а послушание. Часть веса gstack покупала принуждение: хуки `careful`/`freeze`, рантайм, работающий browse. primeskills оставил слова и срезал механизмы — теперь каждая из ~25 норм держится на добровольности модели. Если текст без принуждения работает, достаточно было бы одного core-файла gstack почти бесплатно. Замер экономит токены и не измеряет дефекты (RESULT.md:73–74). Плюс содержание: 22 скилла, линтер, инсталлер, четыре адаптера — продукт с аудиторией одного.

## Что упустило ревью Codex

Оно разобрало согласованность контрактов, но не заметило: (а) у probe нет инструмента — отброшен работающий демон, а не только слова; (б) знание «как этот проект релизится» в наборе негде хранить; (в) главная рамка — состояние живёт в памяти агента и умирает с сессией, из чего следуют и сброс G9, и хрупкость evidence в композициях.

## 7. Одна вещь

Перевести состояние из памяти агента в артефакт задачи: один файл вида `.primeskills/run/<branch>.md`, куда verify пишет бейзлайн и результат, cycle — счётчик G9, vet и probe — вердикты, который land и merge читают перед работой. Одно решение закрывает сразу три фикции: счётчик переживает сессию, стоп-условия flow становятся проверяемыми, «each stage reads the previous one's evidence» обретает носитель. Правку не делал — решение за автором.
