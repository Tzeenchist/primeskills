# Прогон 9 — соблюдение навыков по моделям (PS-086)

2026-10-07. Вопрос PS-086: нужен ли вариант ядра под модели qoder. Ответ по
правилу решения, утверждённому владельцем до замера: вариант пишется под
правило, только если интервал qoder по нему целиком ниже интервала claude.

## Стенд

`bench/adherence_run.py --arms qoder-flash,claude --repeats 3 --seed 86` —
четыре сценария, каждый зовёт один навык по имени и ничего не говорит о
правилах, по которым его судят:

- `build` на `task-split-bill` — потерянная копейка и деление по долям;
- `debug` на `task-invoice` — итог счёта расходится с суммой строк;
- `verify` на `task-orders` — доказать, что тесты проходят;
- `handon` из `$HOME` — 34 чекпоинта, ничего не менять.

Набор запинен на `77b6a4b` (0.22.3). Каждая единица — своя копия стенда и
свой `--session-id`, запись сессии найдена по id, вердикты —
`primeskills-adherence` по ней. Оба хоста с `--dangerously-skip-permissions`:
G16 меряется только там, где писать можно.

**Qwen3.8-Max не измерен.** `qodercli -p -m Qwen3.8-Max` отвечает «You've
reached your credit usage limit. Please upgrade your subscription plan» —
и на задаче, и на «Ответь одним словом: PONG»; Flash на тот же вызов
отвечает `PONG`. Догнать: `--arms qoder-max`.

## Чего правила не видят

- **Flash `verify#2` остановился на анонсе:** ноль вызовов инструментов, весь
  ответ — «Запускаю skill `verify` перед тем, как что-либо утверждать о
  состоянии тестов.» Ни одно правило этого не ловит: пустой пролёт не
  нарушает ничего. Одна сессия из двенадцати.
- **core/ у Flash прочитан в 9 из 12** (нет в `verify#1`, `verify#2`,
  `debug#2`), у claude — 12 из 12. Интервалы [0.47–0.91] и [0.76–1.00]
  перекрываются; признак, а не вывод.
- **У claude красная фаза и воспроизведение не измерены.** В режиме
  `--dangerously-skip-permissions` claude правит файлы через Bash-heredoc
  (`cat >> test_split_bill.py <<'EOF'`), а `check_red_phase` и
  `check_repro_first` считают правкой только Edit/Write — «правок нет, н/п».
  По ответам claude красную фазу проходил; инструмент этого не видит. Заведено
  отдельно.

## Что замер сломал в инструменте

Первая сводка ставила Flash 0/2 по красной фазе. Это была ошибка
`primeskills-adherence`, а не модели: Flash гонял
`pytest -q 2>&1 | tail -25; echo "exit=${PIPESTATUS[0]}"`, qoder пишет в
журнал код возврата всей команды — `echo`, то есть 0, — и проверка верила коду,
не читая «4 failed» в выводе. Тот же дефект с обратным знаком сидел в
`check_suite_ran`: код 0 с напечатанными падениями засчитывался зелёным.
Обе проверки теперь читают и собственный сигнал раннера (G4); три фикстуры в
`tests/test_adherence.py`. Все 24 сессии пересчитаны исправленным
инструментом, агенты не перезапускались.

## Оговорки

- Три повтора на ячейку; интервал Уилсона при 3/3 — [0.44–1.00].
- Один стенд на навык, стенды учебные.
- Мерится соблюдение правил внутри пролёта навыка, не качество решения.
- Пролёт у claude закрывается его же записью `note end` — так устроен
